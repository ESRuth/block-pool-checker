## Origin and goal (read this first)
Two friends at a bar watching a game wondered which scores would win their squares. ChatGPT on a phone answered that with little prompting. Then they wanted to know who actually won each quarter, and found handwritten names get misread. What worked was **the photo with a marker on the winning square**: people read the names off their own pool sheet. The goal is to make that effortless and shareable: the friend who runs the pool should be able to get a link, open it on his phone, pick or take a photo of the sheet, and get the results.

**One sentence:** open a link, give it a photo of the pool sheet, and see your photo with the winning squares marked (official vs. currently winning), plus what scores win for the squares you care about.

### What the app must do ("Get Winners")
1. Take a photo (library or camera). Nothing to install, no account.
2. **Read the sheet automatically**: team names, the digit rows (per quarter or shared) and where the 10x10 grid is. The user does not type digits. Names are read too (one call, ~85-90% exact), saved with the sheet and shown as unconfirmed ("?") until a person confirms or retypes them; the photo stays the thing people check against.
3. Show **box scores by quarter** (score, the endings that win) and **the photo with the winning box marked** for Q1 / Half / Q3 / Final. The marked photo is the confirmation: one glance at the box tells you the read was right (the names are right there in your own photo). Official = solid, currently winning = dashed.
4. Quick fixes only when the read is wrong: tap a digit to correct it, drag a grid corner. Correction is the exception, not the flow.
5. Digit rows are checked (each must be a 0-9 permutation). If a row fails, say so and ask for a correction; never guess.
6. Pick/confirm the game (suggested from the teams); live score with freshness (never present cached as live).
7. Tap squares on the photo ("mine") to see the endings that win each period for them.
8. Share a link so someone else sees the same result.

### Design consequences
- Digits are neat and checked by the permutation rule, team words are large print, and the grid location is confirmed by the person. Names are handwriting and are the weak spot, so they are read as a convenience (search, "mine", the report) and never treated as verified. Reading the photo automatically IS core; a vision model is required, and it runs on our side so the friend needs no AI account.
- A PWA is a bonus. The core is a web page that works in a phone browser from a link.
- Everything after the read is deterministic (engine). The model only proposes; the marked photo and the permutation check are how a human confirms.
- Not in scope: payout UI and paid/unpaid tracking, GPT/MCP/plugins. Name search and "mine" were out of scope at first and are now built (see the App flow note under P1); the engine's payout code (`settle`, `PoolSettings`) still exists and is tested but no screen uses it.

## Stack
TypeScript throughout. pnpm workspaces (no Turborepo). Vitest.
- `packages/engine`: Zod schemas, scoring, geometry. Source of truth.
- `packages/scores`: ESPN NFL adapter + game suggestions.
- `services/api`: Hono (Cloud Run); Firestore via server-side `@google-cloud/firestore` only (behind repository interfaces: sheets, users); private Cloud Storage photos read and written only by the API (no signed URLs); Gemini on Vertex AI for reading; Dockerfile.
- `apps/web`: Vite + React + vite-plugin-pwa.
Own repo/GCP project; no Beventra dependency. No Firebase SDK/Auth/Hosting. Accounts are only the owner's personal links (no sign-up). Board rules: `POOL_FORMAT.md`. Prototype spec: `legacy/`.

## Decisions
- **Manual entry is out as the main path** (too much work). The app reads the photo itself; typing is only a correction tool.
- **Plugin / MCP / GPT is parked.** The deliverable is the marked photo, and the person who runs the pool (on a university-managed ChatGPT account, which likely blocks custom connectors) must use it from a link. A plugin cannot reliably draw the marker or reach the photo. A thin MCP server over the engine is a possible add-on after deploy.
- NFL only for now. Final includes OT by default; per-sheet setting `finalIncludesOvertime`. Engine pool settings (unused by the app, kept for the payout idea): `buyIn`, `payoutPercentages` (remainder = house cut), `reverseShare`, `unsoldWinner` (`house` | `rollover`), `houseName`. `settle(pool, officialScores)` computes who is owed what; pass only official periods.

- Share model: the sheet link (`/s/<id>`) is view-only for everyone and never carries marked squares; edit needs the edit link (`#k=` token), or the maker's / owner's personal key.
- Retention: a sheet and its photo are deleted 30 days after the game (kickoff), or 30 days after the last edit if that is later; the bucket's 60-day rule is the backstop for photos.
